# JAT Application Software Outline

## Overview
JAT (Just Another Tool) is an asynchronous, workflow-driven orchestration engine designed to manage complex agent interactions, task execution, and state persistence. It features a modular architecture built on FastAPI, SQLAlchemy, and Pydantic.

---

## 1. API Layer (`src/api/`)
The entry point for all external interactions, handling HTTP requests, security, and routing.

### 1.1 Application Factory (`src/api/server.py`)
*   **User Summary**: The main server that starts the application and connects all parts together.
*   **Developer Explanation**: Creates the FastAPI instance, registers routers, adds middleware (security, logging), and manages lifespan events (startup/shutdown).
*   **Key Functions**:
    *   `create_app()`: Initializes the FastAPI app and configures dependencies.
    *   `lifespan()`: Manages async resources like database connections during app lifecycle.

### 1.2 Middleware (`src/api/middleware/`)
*   **User Summary**: Security guards that check every request before it reaches the logic.
*   **Developer Explanation**: Contains Starlette/FastAPI middleware for CORS, HTTPS enforcement, and request ID tracking.
*   **Files**:
    *   `security.py`: Enforces HTTPS, adds security headers (HSTS, X-Frame-Options).
    *   `logging.py`: Injects unique Request IDs into log contexts for tracing.

### 1.3 Routes (`src/api/routes/`)
Modular endpoints grouped by domain.

#### Health & System
*   **File**: `src/api/routes/health.py`
*   **Features**:
    *   `GET /health`: Checks if the service is alive.
    *   `GET /ready`: Checks if dependencies (DB, agents) are ready.
*   **Functions**: `health_check()`, `readiness_check()`.

#### Sessions
*   **File**: `src/api/routes/sessions.py`
*   **Features**: Create, list, and retrieve chat sessions.
*   **Functions**:
    *   `create_session()`: Starts a new conversation context.
    *   `list_sessions()`: Returns user's history.
    *   `get_session()`: Retrieves specific session details.

#### Messages
*   **File**: `src/api/routes/messages.py`
*   **Features**: Send messages, stream responses, and retrieve history.
*   **Functions**:
    *   `send_message()`: Accepts user input, triggers workflow, returns response.
    *   `stream_message()`: Yields tokens as they are generated by agents.
    *   `get_history()`: Fetches message thread for a session.

#### Files
*   **File**: `src/api/routes/files.py`
*   **Features**: Upload, download, and delete attachments.
*   **Functions**: `upload_file()`, `download_file()`, `delete_file()`.

#### Providers & Models
*   **File**: `src/api/routes/providers.py`, `src/api/routes/models.py`
*   **Features**: Manage LLM provider configurations and available models.
*   **Functions**: `list_providers()`, `configure_provider()`, `list_models()`.

## 2. Core Logic (`src/core/`)
The brain of the application, handling orchestration, workflows, and agent management.

### 2.1 Workflow Engine (`src/core/workflow/`)
Executes Directed Acyclic Graphs (DAGs) of tasks.

*   **Graph Structure** (`src/core/workflow/graph.py`)
    *   **User Summary**: Defines the map of tasks and how they connect.
    *   **Developer Explanation**: Pydantic models and classes defining `Node`, `Edge`, and `WorkflowGraph`. Validates DAG integrity (no cycles).
    *   **Functions**: `add_node()`, `add_edge()`, `validate_dag()`.

*   **State Management** (`src/core/workflow/state.py`)
    *   **User Summary**: Tracks the progress of a workflow (pending, running, completed).
    *   **Developer Explanation**: Enum definitions and state machine logic to transition workflow instances. Handles persistence of state snapshots.
    *   **Functions**: `transition_state()`, `get_current_state()`, `snapshot()`.

*   **Executor** (`src/core/workflow/executor.py`)
    *   **User Summary**: The worker that actually runs the tasks defined in the graph.
    *   **Developer Explanation**: Async loop that traverses the DAG, resolves dependencies, and invokes the correct handler for each node. Implements retry logic.
    *   **Functions**: `execute_workflow()`, `run_node()`, `handle_retry()`.

*   **Facade** (`src/core/workflow_engine.py`)
    *   **User Summary**: (Legacy) Simple interface to start a workflow.
    *   **Developer Explanation**: Backward-compatible wrapper importing from `workflow/` modules.

### 2.2 Agent System (`src/core/agents/`)
Manages AI agents and task dispatching.

*   **Registry** (`src/core/agents/registry.py`)
    *   **User Summary**: A directory of all available agents.
    *   **Developer Explanation**: Singleton pattern storing agent definitions (name, capabilities, model config).
    *   **Functions**: `register_agent()`, `get_agent()`, `list_agents()`.

*   **Dispatcher** (`src/core/agents/dispatcher.py`)
    *   **User Summary**: Assigns tasks to the best-suited agent.
    *   **Developer Explanation**: Logic to match task requirements with agent capabilities. Handles load balancing if multiple instances exist.
    *   **Functions**: `dispatch_task()`, `select_agent()`.

*   **Lifecycle** (`src/core/agents/lifecycle.py`)
    *   **User Summary**: Manages agent startup, shutdown, and health.
    *   **Developer Explanation**: Hooks for initializing agent contexts (e.g., loading system prompts) and cleanup.
    *   **Functions**: `initialize_agent()`, `terminate_agent()`.

*   **Coordinator** (`src/core/coordinator.py`)
    *   **User Summary**: (Legacy) High-level manager for agent interactions.
    *   **Developer Explanation**: Backward-compatible wrapper importing from `agents/` modules.

## 3. Data Access Layer (`src/repositories/`)
Abstracts database operations, ensuring business logic doesn't depend on SQL.

*   **Base Repository** (`src/repositories/base.py`)
    *   **Explanation**: Generic CRUD interface using SQLAlchemy async session.
    *   **Functions**: `get()`, `list()`, `create()`, `update()`, `delete()`.

*   **Entity Repositories**:
    *   `src/repositories/users.py`: Manages user accounts and auth data.
    *   `src/repositories/sessions.py`: Handles conversation session records.
    *   `src/repositories/messages.py`: Stores chat history and metadata.
    *   `src/repositories/files.py`: Manages file metadata and storage paths.

*   **Legacy Facade** (`src/db.py`)
    *   **Explanation**: Deprecated module re-exporting repository functions for backward compatibility.

---

## 4. Configuration & Utils (`src/config/`, `src/utils/`)

### 4.1 Settings (`src/config/settings.py`)
*   **User Summary**: Controls how the app behaves (ports, keys, paths).
*   **Developer Explanation**: Pydantic `BaseSettings` class loading from `.env` and environment variables.
*   **Functions**: `get_settings()` (singleton).

### 4.2 Security (`src/utils/security.py`)
*   **User Summary**: Tools for keeping data safe.
*   **Developer Explanation**: Password hashing (bcrypt), JWT token generation/validation, API key verification.
*   **Functions**: `hash_password()`, `verify_token()`, `generate_api_key()`.

### 4.3 Logging (`src/utils/logging_config.py`)
*   **User Summary**: Sets up the recording of events.
*   **Developer Explanation**: Configures `structlog` for structured JSON logging, including formatters and processors.
*   **Functions**: `setup_logging()`.

---

## 5. Prompts & Templates (`src/prompts/`, `src/templates/`)

### 5.1 System Prompts (`src/prompts/system_prompts.py`)
*   **User Summary**: The instructions given to AI agents.
*   **Developer Explanation**: Constants containing large strings used as system messages.
*   **Note**: Planned for migration to `src/templates/` (YAML/JSON).

### 5.2 Templates (`src/templates/`)
*   **User Summary**: External files for dynamic content.
*   **Developer Explanation**: Directory for storing prompt templates, email bodies, or other text assets separate from code.

---

## 6. Client Integrations (`src/clients/`)

*   **Local DB Client** (`src/clients/local_db.py`)
    *   **Explanation**: Low-level SQLite/PostgreSQL driver wrapper. Used by repositories.
*   **HTTP Clients** (`src/clients/http_client.py`)
    *   **Explanation**: Wrapper around `httpx` for external API calls (LLM providers), handling retries and timeouts.

*   **Fixtures**: `tests/conftest.py` provides shared setup (async client, db session).
